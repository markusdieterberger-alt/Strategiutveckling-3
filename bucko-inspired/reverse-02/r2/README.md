## Exact rerun

Reference environment: Python 3.12.14, NumPy 2.3.5, pandas 2.2.3, C++17 compiler and zlib headers/library. Linux example (from the newly extracted directory):

```bash
python -m venv .venv
. .venv/bin/activate
python -m pip install numpy==2.3.5 pandas==2.2.3
python reverse02/code/run_all.py --workers 4
```

The Python driver compiles the fixed C++ kernel, creates every candidate outcome, runs 15 primitive and seven full lifecycle tests, compares 8,640 Python/C++ paths, runs all account cells, audits every normalized event, rebuilds report tables and checks the previously delivered result matrix and ledger hashes. C++ is used for volume; the independent account reference and orchestration are Python. Allow several GB of free disk space. No network access is needed after dependencies and packages are installed. `--workers` changes scheduling only. The released PDFs/XLSX are frozen reviewed presentation artifacts, not regenerated by the driver; the numerical results are regenerated and compared column by column.

If the full unchanged `reverse01/` source tree is present as a sibling, `--from-traces` rebuilds the frozen transport inputs from its cached signal traces. It retains prior warmup, contract resets, holiday blackouts and rolling policy. It does not recompute or optimize signals.

For one inspectable account, after placing the delivered ledger parts in `delivery_data/`:

```bash
python reverse02/code/expand_ledger.py --dataset master --config 448 --path 258 --output account_example.csv
```

The expander joins the actual normalized ledger to source candidate prices, quantity, risk, source timestamps, phase and cash. It verifies phase trade counts and P&L against the account summary. `phase_equity_after_trade` is relative phase profit before any final payout withdrawal. An unresolved execution is NaN cash, never a fabricated winning or losing fill. Paths 0–257 (master) and 0–1655 (legacy) are chronological; subsequent 4,096 paths are bootstrap scenarios. Bootstrap source timestamps are not consecutive real calendar time.

## Model and interpretation

- S: reverse direction with a new-side known structural stop. M: reverse using the original structural stop distance about the observable entry open. Their populations remain separate.
- RR = 1, .75, .50, .33, .20, .10; risks = 100, 200, 300, 400, 500, 575 USD. Funded risk is capped at 200 USD, an explicit own policy.
- Four fill scenarios: BASE1, SLIP2, DELAY60 and DELAY60_SLIP2. Three day policies: P0, P300, P600. Actual source signal definition/filters stay fixed.
- One position, integer contracts, next observed open, stop-first OHLC ties, target penetration, adverse slippage and commission. Cash flow uses USD2/point and a .25-point tick.
- The exact-mirror outputs distinguish forced mathematical negation, independent brackets at fixed opportunities, and the separately executable one-position book.
- Status codes: 1 evaluation MLL, 2 evaluation inactivity, 3 evaluation timeout, 4 funded MLL, 5 funded inactivity, 6 funded timeout, 7 first payout eligibility, 8 censored, 9 unresolved data. DLL is a soft day stop. Timeout is a research restart policy, not a firm rule breach.
- Fees 50/75/100/150 USD and approval assumptions are scenarios. The current Flex checkout price and signed funded agreement were not verified. Payout is numeric eligibility conditional on approval, not a received bank payment. The model ends at the first request and assigns no residual account value. Request timing excludes unmeasured approval latency; the stated two business days begin after approval.
- Bootstrap CIs measure simulation error conditional on the empirical five-session generator. They do not establish future-market reliability. Master and legacy are separate; legacy has unresolved paths. The best rows were observed after multiple testing and are biased upper benchmarks.
- No tick orderflow, live execution, TradingView compilation, challenge purchase or automation occurred. CT Scalper and all prior Bucko implementations remain unchanged.
